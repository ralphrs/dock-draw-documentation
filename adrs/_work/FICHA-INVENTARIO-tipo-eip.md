# Ficha: formas dos Enterprise Integration Patterns (tipo 9 da `DEC-0026`)

Levantamento da lacuna registrada na `DEC-0026`, tipo 9, "Arquitetura de integração": "Em parte, faltam os Enterprise Integration Patterns". Segue o mesmo método do `adrs/_work/INVENTARIO-formas-por-diagrama.md`, reaproveitando as dez primitivas de `dok-draw-app/src/components/editor/element-shape.tsx` (`rect`, `boundary`, `person`, `cylinder`, `pipe`, `hexagon`, `browser`, `terminal`, `bucket`, `folder`) e as oito primitivas novas já identificadas para formas básicas (elipse, losango, triângulo, paralelogramo, documento, nuvem, nota, texto solto).

## O que falta além de forma

> [!WARNING]
> Lacuna: Point-to-Point Channel e Publish-Subscribe Channel diferenciam o mesmo `pipe` por uma seta sobre o canal, não por uma forma de nó nova. O `C4Edge` de hoje (`dok-draw-app/src/components/editor/c4-edge.tsx`) cobre ponta única (`arrow`, `open`, `diamond`, `circle`, `none`), suficiente para Point-to-Point. Não cobre uma ponta bifurcada em várias setas, que o ícone de Publish-Subscribe Channel usa para indicar cópia a cada receptor. Dono: ADR que tratar arestas de canal, para decidir entre uma `EdgeEnding` nova ou um selo textual sobre o canal.

> [!WARNING]
> Lacuna: Message Router, Message Filter, Message Translator, Message Endpoint, Aggregator e Splitter usam o mesmo retângulo verde como corpo, diferenciados por um pictograma vetorial pequeno dentro. Isso não é o problema 3 de `adrs/_work/ADR-015-escopo.md` (compartimento de atributos e métodos, lista estruturada de texto), é mais próximo do desenho bakeado em código que já existe em `browser` e `terminal` (`dok-draw-app/src/components/editor/element-shape.tsx`, linhas 165 a 207), sem entrada em `adrs/_work/ADR-015-escopo.md`. Dono: ADR 015, para decidir se cada pictograma vira `shape` própria ou se o vocabulário de formas ganha um mecanismo de ícone interno reaproveitável entre notações.

> [!WARNING]
> Lacuna: o octógono vermelho do Dead Letter Channel é um selo pequeno sobre o `pipe`, sem primitiva equivalente entre as dez existentes, as oito novas de formas básicas ou o vocabulário de compartimento do problema 3. Dono: ADR 015, para decidir entre uma forma de octógono dedicada, um selo textual (por exemplo, rótulo "DLQ" com cor de alerta) ou tratamento fora do vocabulário de formas.

> [!WARNING]
> Lacuna: não há confirmação de que o Diagram Studio precisa de um nó dedicado para Message. Nos diagramas de arquitetura de integração do próprio catálogo, a mensagem aparece como conteúdo em trânsito num canal, raramente como caixa isolada no desenho estático. A forma composta descrita nesta ficha existe no ícone do catálogo, sem evidência de uso como nó de diagrama de arquitetura. Dono: humano, para decidir se Message entra no escopo de forma ou fica fora por não ser desenhado como nó nos exemplos de arquitetura de integração.

Onze formas ao todo. Quatro reaproveitam `pipe` já existente (Message Channel, Point-to-Point Channel, Publish-Subscribe Channel, Dead Letter Channel), as duas variantes de canal sem custo de forma nova, só de aresta. As outras sete pedem primitiva nova: Message (composta, molde `person`) e seis formas compostas sobre `rect` no molde de `terminal`/`browser` (Message Router, Message Filter, Message Translator, Message Endpoint, Aggregator, Splitter).
