# Modelo de issue: trilha de ADR (sessão B)

Projeto `DDP`, tipo `Tarefa`. Responsável: Sessão B. Rótulos: `sessao-b`, `trilha-adr`, o ADR (`adr-002`), e `encerrar` quando for o caso.

O resumo da issue começa pelo que ela entrega, não pelo número: "Escrever o ADR 007 (Renderização)", não "Tarefa de ADR 007".

Descrição:

```md
## Objetivo

Uma frase: o que existe quando a tarefa termina.

## Contexto

Arquivos a ler, decisões que valem (D-n, contratos do ledger), o que já foi tentado. Caminho de cada evidência, nunca o documento colado.

## Entregáveis

Caminhos exatos dos arquivos a produzir ou alterar.

## Critério de pronto

Lista verificável. Cada item diz como verificar: comando, contagem, teste, saída esperada.

## Restrições

O que não fazer. Travas: prazo, saída definida se falhar, limites de escopo. Categorias de aprovação que a tarefa vai encontrar pelo caminho.
```
