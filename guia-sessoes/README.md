# Guia das sessões A, B e C

| Arquivo | Para quê |
| --- | --- |
| `PROTOCOLO.md` | Regras de comunicação das três sessões: pastas, nomes, ciclo de vida, desenvolvimento no app, aprovação humana, escuta, encerramento |
| `PROMPT-SESSAO-A.md` | Abertura da sessão A (arquiteto e scrum master): missão, trilhas, roteiro dos ADRs, sprints de desenvolvimento |
| `PROMPT-SESSAO-B.md` | Abertura da sessão B (executor de ADR) |
| `PROMPT-SESSAO-C.md` | Abertura da sessão C (desenvolvedora, roda no repositório do app) |
| `CONFIGURACAO.md` | Permissões dos dois repositórios, ordem de início e retomada |
| `templates/` | Modelos: `TASK.md` (tarefa de ADR), `DEV-TASK.md` (tarefa de desenvolvimento), `QUESTION.md`, `ANSWER.md` |
| `bin/` | `wait-for.sh`, `move.sh`, `next-id.sh`, `seen.sh`. Rodam a partir desta raiz de onde quer que sejam chamados |

A trilha de ADR termina com o ADR 012 aceito. A trilha de desenvolvimento termina quando a meta definida pelo humano for atingida. A sessão A encerra cada trilha com uma tarefa do tipo `encerrar`.
